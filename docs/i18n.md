# Translations: what is translated, and how

Languages: zh-CN, ja, ko, es, pt-BR, de, fr. English is the default and has no prefix.

The translations were written by AI and have not been reviewed by native speakers.

## What is translated

| Part | Address | Where the words are |
|---|---|---|
| Home | `/<locale>` | `messages/<locale>.json`, `Home` |
| Online face swap overview | `/<locale>/face-swap` | `messages/<locale>.json`, `FaceSwap`, `OnlineTools` |
| Video FaceSwap page | `/<locale>/facestudio-v` | `messages/pages/<locale>.json`, `video` (Chinese: `app/[locale]/facestudio-v/zh-page.tsx`) |
| Nano FaceStudio Online page | `/<locale>/face-studio` | `messages/pages/<locale>.json`, `faceStudio` |
| Nano ImageEdit page | `/<locale>/image-edit` | `messages/pages/<locale>.json`, `imageEdit` |
| Nano HeadSwap Pro page | `/<locale>/headswap-pro` | `app/headswap-pro/copy.ts` (en, zh-CN, ja), `messages/pages/<locale>.json`, `headswap` (the rest) |
| Nano FaceStudio Pro page (shorter than the English one) | `/<locale>/apps/nano-facestudio-pro` | `messages/pages/<locale>.json`, `pro` |
| Free desktop app pages (shorter than the English ones) | `/<locale>/apps/nano-faceswap`, `nano-facialedit`, `nano-imagetryon` | `messages/pages/<locale>.json`, `faceswap`, `facialedit`, `imagetryon` |
| Prices (figures from the code that charges them) | `/<locale>/pricing` | `messages/pages/<locale>.json`, `pricing` |
| Download page and desktop checkout | same address in every language | `messages/pages/<locale>.json`, `strings`: whole English strings, read through `lib/i18n/strings.ts`; anything missing shows in English |
| Navbar, footer, sign-in, sign-up, credits, My images, My videos | same address in every language | `messages/<locale>.json`, `Ui` |
| Face Studio, ImageEdit and HeadSwap tool screens | same address in every language | `public/i18n/tools-<locale>.json` |

`messages/pages/en.source.json` is the English the translators worked from. It is not shown on the site. When the facts in it change, change the translations too.

## Left in English on purpose

- Legal text: `/terms`, `/privacy`, the footer disclaimer, and the auto top-up terms and consent. `/<locale>/pricing` links to the Terms and says they are in English.
- The prompts sent to the image model: presets, the example chips and the field placeholders. The translated ImageEdit page tells people to write instructions in English.
- Forgot-password and reset-password pages, the account page, the paid desktop app pages other than Nano FaceStudio Pro, release notes, the blog (except the Chinese guides), and the emails Supabase sends.

## Not in this repository

The video studio's screens (the address in `FACESTUDIO_V_STUDIO_URL`) are in the Matrix repository, branch `render-deploy`: `swap_pipelines/ui/public.html`, translated in the browser by `swap_pipelines/ui/i18n/studio.js` and `studio-<locale>.json`, the same way as the tool screens here. `/facestudio-v/launch` sends the language after the `#` of the link (`l=de`), because that address cannot read our cookie. `scripts/check-i18n-coverage.mjs` does not look at that repository; its tests compare the dictionaries' keys.

## How a language is chosen

- Pages with a prefix use the prefix.
- `/auth/*`, `/credits`, `/my-images`, `/facestudio-v/videos`, `/download` and `/checkout` use `negotiateLocale`, and both Stripe checkouts are opened in that language in `middleware.ts`: the `np_locale` cookie, else the browser's `Accept-Language`, else English.
- Tool screens do the same in the browser (`public/i18n/tools.js`). Change the two together.
- `app/components/locale-switcher.tsx` sets the cookie, when someone picks a language and when they browse a page with a prefix. Middleware must not set it: cached pages cannot send cookies.

## Tool screens

`public/i18n/tools.js` replaces a text node or attribute only when its whole text is a key in the dictionary. Anything else stays in English, so a new string fails safe. Keys with `{n}` match numbers. Many keys are pieces of one sentence split by a link or bold word, so a change to the HTML can leave a piece unmatched.

## Checking for missing translations

`node scripts/check-i18n-coverage.mjs` (GitHub runs it on each push) lists keys missing from a language and English in the tool screens and cookie-language pages that is neither translated nor listed in `scripts/i18n-left-in-english.txt`. A failure does not block a deploy.

## Offering a language

`app/components/language-prompt.tsx` offers the translation of an English page, in a small card, to someone whose cookie or browser asks for that language. It never redirects. GA4 events: `language_prompt_shown`, `language_prompt_accepted`.

## Adding a page

1. Add its copy to `messages/pages/en.source.json` and to each language.
2. Add the path to `TRANSLATED_PAGES` in `lib/i18n/locales.ts`. The switcher, nav and footer use this list.
3. Add it to `app/sitemap.ts` with `translatedEntries`, and give the English page `alternates.languages`.
